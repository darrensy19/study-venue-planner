### Findings

#### IMP-019-R1-F01 — High — The form does not consume the exported control contract

- **Status at issuance**: `open`
- **Evidence**: `PLAN.md:1843` requires `app.js` to build every control from `CONTROL_CONTRACT`, with no supported value or numeric bound declared twice. The diff exports the contract in `web/ranking.js:114-118`, but `web/app.js:7-15` retains local origin/mode lists and `web/app.js:252-259` retains `min: "60"`/`step: "15"`; the contract instead accepts duration `[180, 360]` with step 15. `web/app.js:1` imports only `rankVenues`. The app test added by this diff checks only removal of the tolerance declaration, so it cannot catch this drift.
- **Impact**: The promised single source of truth is not implemented. The rendered UI currently offers a 60-minute request that the new validator rejects, and any later contract change can make the form offer invalid tokens or exclude supported ones.
- **Recommended correction**: Import and use `CONTROL_CONTRACT` to construct the origin/mode options and duration/leave-at bounds (keeping renderer-owned labels local), and add a DOM test that proves the rendered controls follow a contract seam/sentinel rather than duplicated literals.

#### IMP-019-R1-F02 — Medium — `resolveHours()` is not total for every documented no-`regular_hours` shape

- **Status at issuance**: `open`
- **Evidence**: The stated contract covers `hours` present but lacking `regular_hours` outright (`PLAN.md:1866-1870`; `web/ranking.js:1094-1102`). But `web/ranking.js:1109-1121` dereferences `hours.current_hours_by_date[targetDate]` before the missing-`regular_hours` guard at line 1126. First-hand probe: `resolveHours({id:"x", hours:{current_hours_valid_from:"2026-09-01", current_hours_valid_through:"2026-09-07"}}, {}, "2026-09-01")` throws `TypeError: Cannot read properties of undefined (reading '2026-09-01')` instead of returning the required failed tag. The new test only selects a date outside that declared window (`tests/js/ranking.test.js:2496-2501`), so it misses this branch.
- **Impact**: A public exported helper violates its fail-closed totality contract for a valid instance of the specified malformed shape; callers other than `rankVenues()` can still crash on a first-ever failed source.
- **Recommended correction**: Detect the failed/no-last-known-good shape before consulting the current-hours window (while preserving the existing loud error for a structurally complete current-hours source whose in-window entry is missing), and add the in-window malformed-shape regression test.

  `TypeError: Cannot read properties of undefined (reading '2026-09-01')`.
- **Response**: real gap, accepted as reported.

  date's `current_hours_by_date` entry is unchanged — that check still runs after the new guard, since
  `regular_hours` being present no longer short-circuits past it.

  exact scenario (target date inside the window, `current_hours_by_date` even has a real entry for
  it, but no `regular_hours` at all), asserting the failed tag rather than a throw; one confirming the
  still-loud case (a structurally complete current-hours source, via `makeVenue`, missing one
  in-window date's entry) still throws, so the fix does not relax that data-integrity check. Reverting
  the fix reproduced both failures; restoring passed both.
