### Findings

#### IMP-005-R1-F01 — Medium — Parser does not fail closed for unrepresentable values or every malformed input shape

- **Status at issuance**: `open`
- **Evidence**: `web/ranking.js:176-185` accepts arbitrary-length digit captures and converts them with `Number()` without a finite/safe-integer guard. First-hand probe `normaliseTravelBand(\`1-${"9".repeat(400)}m\`)` returned `{ kind: "present", mid: Infinity, upper: Infinity }`. The malformed branch at `web/ranking.js:178` interpolates `JSON.stringify(band)`; `normaliseTravelBand(1n)` throws `TypeError: Do not know how to serialize a BigInt`, and an object with a throwing `toJSON()` also throws. The tests at `tests/js/ranking.test.js:589-593` cover only stringify-safe non-string values.
- **Impact**: Invalid metadata can produce non-finite travel minutes or throw rather than return the required rejected/malformed result. Either outcome defeats the assignment's fail-closed negative-path contract and can corrupt downstream minute arithmetic once wiring is added.
- **Recommended correction**: Reject parsed edges unless both are safe finite integers before comparing/deriving the midpoint, and make malformed-value diagnostics non-throwing (or avoid serialising arbitrary values). Add tests for an overflow-length numeric band and at least a `BigInt` or throwing-`toJSON` non-string input, asserting `{ kind: "malformed" }` without throwing.

### Finding dispositions

#### `IMP-005-R1-F01` — `accepted`

- **Factual assessment**: `confirmed` — independently reproduced both failure modes against the
  actual code before making any change. Calling `normaliseTravelBand` with a 400-nine-digit upper
  edge (the reviewer's overflow-length probe) returned `{kind: "present", mid: Infinity, upper:
  Infinity}` (confirmed via direct object inspection, not `JSON.stringify`, which silently turns
  `Infinity` into `null` and would have hidden the bug). `normaliseTravelBand(1n)` threw `TypeError:
  Do not know how to serialize a BigInt`, and an object with a throwing `toJSON()` threw the same
  way — both from the malformed branch's `JSON.stringify(band)` call.
- **Independent verification**: `[0-9]+` has no length bound, so `Number(m[2])` on a long enough
  digit string overflows past `Number.MAX_VALUE` to `Infinity`; `!(lo < hi)` does not catch this
  since `1 < Infinity` is `true`, so the value reaches the success branch unrejected. This is
  specific to this function — the sibling `normaliseEdge`/`normaliseBand` (return-transport clock
  bands) are constrained to exactly 2-digit captures and can never overflow. `PLAN.md` states no
  numeric ceiling for travel bands, so the fix could not invent one; `Number.isSafeInteger` rejects
  both the overflow case and any finite-but-unsafe magnitude in one check, without asserting a
  minutes cap the contract never specifies.
- **Response**: Accepted as reported. `normaliseTravelBand` now requires both parsed edges to satisfy
  `Number.isSafeInteger` before the `lo<hi` ordering check or the midpoint derivation, rejecting with
  `{kind:"malformed", reason:"edge outside the safe integer range: (...)"}`. The malformed branch's
  diagnostic now goes through a new `describeUnparseable` helper that wraps `JSON.stringify` in
  `try/catch` and falls back to `` `<unserialisable ${typeof value}>` `` on failure — the only
  callsite that ever stringifies an arbitrary, unvalidated value; the two other malformed branches
  interpolate already-safe `Number`s and are unaffected.
- **Changes made**: `web/ranking.js` — added `describeUnparseable`; `normaliseTravelBand` calls it
  instead of a bare `JSON.stringify(band)`, and gains a `Number.isSafeInteger` guard on `lo`/`hi`
  before the existing ordering check. `tests/js/ranking.test.js` — 4 new regression tests: an
  overflow-length digit band, an edge one past `Number.MAX_SAFE_INTEGER`, a `BigInt` input, and a
  throwing-`toJSON()` object, each asserting `{kind:"malformed"}` and, for the latter two,
  `assert.doesNotThrow` around the call itself.
- **Verification**: `node --test tests/js/*.test.js` — `142` passed, `0` failed (the pre-existing 138
  plus the 4 new regression tests; no other test's expected values changed).
