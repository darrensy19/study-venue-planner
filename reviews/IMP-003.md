### Findings

#### IMP-003-R1-F01 — High — Malformed histogram values can produce a determined `typical` band

- **Status at issuance**: `open`
- **Evidence**: `web/ranking.js:572-605` counts all open-hour records as coverage and passes their unvalidated `busyness` values into the median/delta calculation. With six open-hour entries and the arrival entry `{hour: 10, busyness: undefined}`, a first-hand module probe returned `{band: "typical", delta: NaN, medianUsed: 50, coverageHours: 6}` (the JSON representation shows `delta: null`). `tests/js/ranking.test.js:1295-1326` covers too-few, absent, and missing-arrival buckets, but no malformed value or duplicate-hour case. Six duplicate records for the same open hour likewise satisfy `filtered.length` and returned `peak`, although there is only one populated hourly bucket.
- **Impact**: A corrupted or duplicate Popular Times record bypasses the coverage floor and can invent a determined condition—specifically `typical` for a missing/non-numeric arrival value—instead of the required `unknown` fallback. That in turn marks `seat_confidence` evidence `normal`, contrary to the decision-model rule that missing busyness must never be treated as typical and source failure must not invent conditions.
- **Recommended correction**: Before coverage and median calculation, validate the usable weekday histogram as one finite, in-range numeric value for each integer hour, with no duplicate hours. Treat malformed/duplicate data (or exclude it such that the distinct valid-hour coverage falls below the floor) as `band: "unknown"` with an explicit reason; add adversarial tests for a missing/non-finite/out-of-range value and duplicate-hour records, including the case that duplicates would otherwise meet `MIN_HISTOGRAM_HOURS`.
