# CLAUDE.md

This is a personal tool. Read [plan.md](plan.md) first — it is the spec and the architecture doc; don't duplicate it here.

## Workflow

- Run on `opusplan`. Enter plan mode at the start of each phase — that's what makes Opus engage; without it this session runs on Sonnet.
- Before writing any code, critique plan.md against the actual repo and environment as they exist right now, not as assumed when the plan was written. Say what's wrong before implementing around it.
- Work one phase at a time, in the order in plan.md (0 → 1 → 2 → 3). Don't build ahead — e.g. don't scaffold Phase 2 seat-logging code while Phase 1 is still open.
- Log resolved open questions and any deviation from plan.md in [decisions.md](decisions.md), not in a comment or a chat reply that disappears.

## Non-negotiables (see plan.md for the reasoning)

- No backend, no server, no API keys shipped in `web/`. Static files only.
- Vanilla HTML/CSS/JS in `web/` — no framework, no build step — following the four constraints in plan.md's "Constraints — write vanilla in a React-shaped way" section.
- `data/*.json` is generated by the scripts in `scraper/` and `analysis/` and committed, not fetched live.
- `seatlog.csv` in iCloud Drive is append-only. Never rewrite it from code.
